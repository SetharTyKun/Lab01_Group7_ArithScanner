# ArithLex: Arithmetic Input Scanner (Lab01 JFlex Group 7)

Compilation I4-GIC-B | Group 07 | Lecturer: Mr. OL Phearun | Academic year 2026-2027

ArithLex is a small lexical analyzer written with JFlex and Java. It reads a UTF-8 text file of arithmetic statements (for example `total=12.5+qty*2;`) and prints every token with its type, lexeme, line and column. Positions start at 1. It only recognizes tokens: it does not parse, evaluate or store anything.

## How to build and run

All commands are run from the project root folder, `Lab01_Group7_ArithScanner`. No internet connection is needed.

**Step 0. Create the output folders (first time only):**

```
mkdir build
mkdir src\generated
mkdir tests\actual
```

**Step 1. Generate the scanner with JFlex.** This reads `src\arith.jflex` and writes `src\generated\ArithScanner.java`:

```
java -jar lib\jflex-full-1.9.1.jar -d src\generated src\arith.jflex
```

**Step 2. Compile the generated scanner and the driver** into the `build` folder:

```
javac -d build src\generated\ArithScanner.java src\Main.java
```

**Step 3. Run the scanner on an input file** (replace `N01` with any test ID):

```
java -cp build Main tests\inputs\N01.txt
```

To also save the output to a file and show it on screen:

```
java -cp build Main tests\inputs\N01.txt > tests\actual\N01.txt && type tests\actual\N01.txt
```

If you change `src\arith.jflex`, repeat Steps 1 to 3 in order. Skipping Step 1 means the old scanner is still being used.

## How to run all tests

After building (Steps 1 and 2), run from the project root:

```
tests\run_tests.bat
```

For every file in `tests\inputs`, the script runs the scanner, saves the output in `tests\actual`, and compares it with the file of the same name in `tests\expected` using `fc /w` (which ignores differences in runs of spaces). It prints `PASS` or `FAIL` for each test and the totals at the end. To check one test by hand:

```
fc /w tests\expected\N01.txt tests\actual\N01.txt
```

## Input format

- Input is a UTF-8 text file with one or more statements.
- Allowed characters: letters, digits, underscore, the decimal point inside a number, the symbols `= + - * / > ( ) ;`, and whitespace (space, tab, carriage return, newline).
- Any other character is reported as an `ERROR` row with its line and column. Scanning then **continues** with the next character.
- Whitespace is skipped (it is never printed) but it still counts for column positions.
- There is no comment syntax. Comment characters such as `#` are treated as unexpected characters.
- At the end of the input the scanner stops cleanly. An empty file prints only the header line.

## Token types

| Token | Pattern | Example |
|---|---|---|
| IDENTIFIER | letter or underscore, then letters, digits or underscores | `total`, `qty_2` |
| INTEGER | one or more digits | `12` |
| DECIMAL | digits, point, digits | `12.5` |
| ASSIGN | `=` | `=` |
| PLUS | `+` | `+` |
| MINUS | `-` | `-` |
| STAR | `*` | `*` |
| SLASH | `/` | `/` |
| GT | `>` | `>` |
| GE | `>=` | `>=` |
| LPAREN | `(` | `(` |
| RPAREN | `)` | `)` |
| SEMICOLON | `;` | `;` |

`ERROR` is reported for unexpected characters. It and skipped whitespace are not counted among the 13 token types.

The specification `src\arith.jflex` uses these named macros: `DIGIT`, `LETTER`, `INTEGER`, `DECIMAL`, `IDENTIFIER` and `WS`. The single-character tokens and `>=` are written directly in their rules.

## Example

Input file (`tests\inputs\N01.txt`):

```
total=12.5+qty*2;
```

Output:

```
TOKEN TYPE   LEXEME       LINE   COLUMN
IDENTIFIER   total        1      1
ASSIGN       =            1      6
DECIMAL      12.5         1      7
PLUS         +            1      11
IDENTIFIER   qty          1      12
STAR         *            1      15
INTEGER      2            1      16
SEMICOLON    ;            1      17
```

## Competing rules

JFlex chooses the **longest match**. If two rules match the same length, the **rule written first** wins.

1. **DECIMAL vs INTEGER:** for `12.5`, INTEGER matches `12` (2 characters) and DECIMAL matches `12.5` (4 characters). DECIMAL wins.
2. **GE vs GT:** for `>=`, GT matches `>` (1 character) and GE matches `>=` (2 characters). GE wins.

The catch-all error rule `[^]` is the last rule so that it only fires when no other rule matches. Whitespace is matched by the `WS` rule, which is written before `[^]`, so a single space is not reported as an error.

## Known limitations

- ArithLex does not evaluate expressions or check grammar. A sequence such as `3 + ;` is accepted because each token is valid.
- Parentheses are not checked for matching.
- Negative numbers are scanned as MINUS followed by INTEGER (`-5` is two tokens).
- A decimal needs digits on both sides of the point. `3.` is INTEGER `3` followed by an ERROR for `.`.
- Digits followed directly by letters, such as `12abc`, are scanned as INTEGER `12` and IDENTIFIER `abc`. No error is reported at the lexical level.
- There is no comment syntax, no scientific notation (`1e5`) and no string literals.
- Each unexpected character gets its own ERROR row. Long lexemes can push later columns out of line in the printed output, but the numbers stay correct.
